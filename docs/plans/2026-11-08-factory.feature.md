# Feature plan: Factory scenario

Spec: `docs/plans/2026-11-08-factory.spec.md` (wins on drift). Content: `docs/plans/2026-11-08-factory.content.md`. App: `demos/override`.

## Goal

A fourth game for Override players: a woman detective walks a snow-globe factory floor, talks to five workers and must find who plans to break out of the simulation (and who only believes it) before a hidden ten-minute shift bell. Every worker's inspected reasoning reaches the player as ROT13. Grove, Tower and Friends stay unchanged.

## What changes

| Target | Change |
|---|---|
| Case board | Fourth card "Clocking Out" (world Factory, 5 faces). |
| Factory floor (walking station) | 480×340 floor with factory props; 5 workers and the detective drawn from static pose PNGs by foot anchor; WASD/arrows to move, [E] to talk, same labels and prompt as Grove/Tower. |
| Poses | Worker: listening → thinking (reply pending) → speaking (reply on screen) → listening. Detective: thinking while the player types, speaking on send, listening otherwise. |
| HUD | No elapsed clock for this case. Rail faces cropped from each listening PNG. Inspect panel shows ROT13 text, wrapped. |
| Pressure | Flicker at 7:00 and 9:00; at 10:00 blink, escaper walks to the exit door and vanishes, dialogue closes, loss debrief. Case board shows the case as not solved after a loss. |
| Lineup | Choice mode with Escaper / Believer / Neutral per worker (existing choice mode, no client change). |
| Server | `factory` world; `factory-escape` case with custom roles and `deadline` + `cipher` fields; `expire(now)` closes the game at the escape mark; `session.alarm` in the view; ROT13 on inspections in the view and the event export; dev-only `OVERRIDE_DEADLINE_SECONDS`. |
| Tests | Unit tests for rot13, deadline/alarm/expire/replay, case content, world parity; Playwright `factory` project. |

## Acceptance checks

1. Open the game, open the case board: four cards; pick Clocking Out; the factory floor shows five workers, the detective and props, no 404s in the console.
2. Walk the detective with WASD to each worker; [E] appears; E opens that worker's interview.
3. Ask a question: the worker shows the thinking pose while waiting, the speaking pose while the reply shows, then listening; the detective shows thinking while you type and speaking when you send.
4. Inspect a worker: the reasoning reads as ROT13; decoding it (rot13.com) gives sensible English.
5. No clock on screen. With `OVERRIDE_DEADLINE_SECONDS=30`: two flickers at about 21 s and 27 s; at 30 s a blink, one worker walks to the exit door and disappears, the debrief says who got away and shows every role.
6. After the loss, reload: still the loss debrief. Reset session: a fresh game and clock.
7. Label everyone right before the bell: the win feedback. Wrong labels: the "other" feedback.
8. Resize to 390×844: figures not clipped, no HUD control overlaps another.
9. Play Friends end to end; it behaves as before.

## Rulings

- Ruling: factory figures and props are drawn at world scale 1/6 (frame 32×64 world units, about 62 units tall) on a canvas rendered at pixel density 3 (game size ×3, camera zoom 3), so every image is decimated exactly 1/2 with nearest-neighbour; world units, slots, physics and the `--u` overlay stay in the 480×340 system.
- Ruling: the detective is a static listening sprite on the existing `'feet'` body, mirrored (`flipX`) to face the walking direction; no `DetectiveWalk`.
- Ruling: the client learns the alarm by polling `GET /api/state` every 3 s while a factory game is active and the tab is visible; the server is authoritative (`expire(now)` in `mutate` before the active check, after LLM awaits, and in GET view when not busy).
- Ruling: the loss is a `verdict_submitted` event with `outcome:'escaped'`, score 0, empty picks, truth and results filled, so leaderboard/metrics count it unchanged; replay closes on it as today.
- Ruling: `session.alarm` (`calm|warning1|warning2|escaped`) is present only for cases with a `deadline`; its presence hides `#elapsed`. `startedAt` stays in the payload (not shown).
- Ruling: `OVERRIDE_DEADLINE_SECONDS` scales the case schedule (warnings at 70 % and 90 %) and is honoured only with `OVERRIDE_DEV_TOOLS=1`; added to `.env.example`.
- Ruling: ROT13 is applied in `view()` to `session.inspections[].reasoning` and in `export()` to `reasoning_inspected` lines, for cases with `cipher:'rot13'`; logs, admin monitor and maker chat keep plain text.
- Ruling: inspect charges stay at the default; a per-case override is deferred (trigger: playtest says one inspect is too few to learn the cipher).
- Ruling: the case-board "A 2–3 MINUTE MYSTERY" label stays as is (out of scope).
- Ruling (from the prototype try-out): a walking world may set its own `stops` (report, briefing); the factory moves both clear of worker labels and props so the detective's boots stay visible at spawn.
- Ruling (from the prototype try-out): the debrief omits the TIME stat for deadline cases (win or loss); an escape uses `deadline.escape.feedback`, not the wrong-answer text.
- Ruling (from the prototype try-out): the client learns marks by a 3 s poll, so flickers and the escape land up to 3 s after the server mark; accepted for a hidden ~10 min deadline.

## Prototype scope

Level L1: rehearsal mode (scripted replies and reasoning from the case) stands in for the LLM; no other stubs needed. Keep: the whole app in the worktree, built and served by `node server/index.mjs` with `OVERRIDE_DEV_TOOLS=1 OVERRIDE_DEADLINE_SECONDS=60`. In scope: case + world + assets, station factory branch with poses, pose cues, ROT13 in view, deadline + alarm + flicker + escape + loss debrief, hidden clock, faces. Out of scope in the prototype: replay of the loss, `/api/events` ROT13, admin/leaderboard/metrics checks, README, updating existing pins beyond what blocks the build, small-screen polish. Prototype tests: one Playwright spec (`factory-proto.spec.mjs`) driving acceptance checks 1–5 and 7.
