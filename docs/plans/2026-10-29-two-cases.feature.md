# Feature plan: two-cases

**Spec:** `docs/plans/2026-10-29-two-cases.spec.md` · **Project root:** `demos/override` · **Orchestrator:** AI

## Goal

Ship the Override demo with exactly two cases, one per world: **The Banana Mystery** (grove, a culprit) and **Lanterns Too Soon** (`tower-echo-bell`, tower, an honest mistake). For the player: two cards on the case board, a monkey case and a wizard case. For the maintainer: three cases move to the archive and every test keeps covering what players can reach.

## What changes

**Web UI**: no code change. The case board shows The Banana Mystery and Lanterns Too Soon instead of the two banana cases. "Next case" after solving one points at the other.

**API**: `/api/cases` lists `banana-mystery` (1, grove) and `tower-echo-bell` (2, tower) with or without dev tools. `start`/`reset` with `banana-control`, `tower-bell-charm` or `tower-missing-yes` → 400 Unknown case.

**Cases**: `server/cases/index.mjs` registers two modules; `tower-echo-bell.mjs` becomes `order: 2, status: 'ready'`. The other three modules stay on disk, unregistered.

**Tests**: retarget every test that starts a dropped case by id to `tower-echo-bell` (session, http, worlds, case-set, browser cases/investigation/provenance/tower); rewrite the case-set rule for a two-case set.

**Docs**: README "Writing a case" and `docs/CASES_PLAN.md` name the live and archived cases.

## Acceptance checks

1. Production server (no dev tools): `curl /api/cases` → two rows, `banana-mystery` then `tower-echo-bell`.
2. Dev-tools server: same two rows; `POST /api/start {"caseId":"tower-bell-charm"}` → 400 Unknown case.
3. Open `/`: two cards; The Banana Mystery is preselected and plays as before.
4. Open `/?case=tower-echo-bell`: tower scene with Wren, Basil, Juniper; reveal 3 clues, ask all three, choose **Nobody** → "Nobody knew it was too soon." and "Right. The rule was broken, but nobody knew it. …".
5. After solving one case, "Next case" names the other one.
6. `npm run cases:prompt -- tower-echo-bell juniper` prints `You play Juniper (The bell-watcher), a young wizard`.
7. `npm test`, `npm run build`, `npm run test:e2e` green; grove pixel baseline unchanged.

**Frozen interfaces:** `defineCase`, `listCases`, `findCase`, `publicView`, `Investigations` API, all `/api/*` payload shapes, log schema v2.

**Untouched tests (import archived modules directly):** `banana-control.test.mjs`, `tower-cases.test.mjs`, `cases.test.mjs` grove-hash test, `session.test.mjs` draft-rejection test.

**Toolchain:** Node `node --test tests/*.test.mjs`; `tsc --noEmit && vite build`; Playwright 1.58 with `--output` isolated per run. Never run unit and e2e at the same time.

## Prototype scope

Ruling: no prototype. The feature adds no code path, screen or data shape: it is a registry edit, one status flip and test retargets. A prototype would be the same diff twice. The try-out is the acceptance checks run against the integration build, recorded as a Ruling.

## Integration outline

One worktree `superlite/two-cases` from `demo/override`. Four tasks:

- **T1 registry**: index.mjs, tower-echo-bell.mjs, case-set.test, tower-echo.test, worlds.test.
- **T2 unit retarget** (after T1): session.test, http.test.
- **T3 browser retarget** (after T1): cases/investigation/provenance/tower specs, playwright.config comment.
- **T4 docs**: README, CASES_PLAN.
